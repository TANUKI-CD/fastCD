# Finite and complex kernel pilot, 2026-11-03

This is a **32-pair pilot**, not the default 10,000-pair campaign. It covers nine finite fields and C, dimensions 2–1024, singles and batches, with 24 balanced blocks and at least 20 ms per observation. Every timed observation replays complete corpus passes. All 3,200 distinct pairs were verified for every timed implementation in both modes before timing: 19,200 checks, followed by 14,400 timed observations.

The runner used a Release GCC build on an Intel Xeon Gold 6148, pinned to CPU 0. See [raw results](results.json), [primary tables](results.md), and [default kernel binary check](kernel-binary-check.json).

## What the primary ratios measure

The direct baseline is the defining four-product CD recursion with degree-specialized scalar field arithmetic and quaternion-sized leaves. Quasilinear uses its coefficient evaluation/reconstruction maps and packed SIMD kernels. The large ratios therefore compare these implementations, including their different coefficient arithmetic and SIMD use; they are not isolated arithmetic-count comparisons or evidence about the fastest possible direct implementation.

For complex coefficients at N=1024, quasilinear is about 43.1 times faster than direct in single mode and about 7% faster than the three-real-product quasilinear baseline. The latter includes input packing and reconstruction and never selects Cariow–Cariowa.

## Defaults and scope

The real AUTO tables are unchanged; finite and complex AUTO select quasilinear. No machine-specific thresholds are selected from this pilot. Larger corpora, other CPUs, degree-12 performance, Python wrapper latency and full memory-working-set effects remain outside these measurements. The standard 10,000-pair campaign is runnable with the documented default command in [the benchmark guide](../../docs/benchmark.md#complex-and-finite-fields).

The [object/archive fingerprints](kernel-binary-check.json) identify the measured default machine code, and [complex-measured.c](complex-measured.c) retains the exact complex source that produced the recorded source hash. This pilot predates later changes to the finite kernels; its timings describe the recorded build only.

Raw corpus files are omitted; their deterministic PCG64 entropy, native dtypes, sizes and SHA-256 hashes are in each result and can be regenerated by `benchmarks/domains.py`. All runtime library buffers and workspaces were preallocated before timing.
